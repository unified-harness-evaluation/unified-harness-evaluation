trajectory summary
What happened in this run
A multi-trip tau-bench travel-agent session: the agent looks up reservations, checks cancellation eligibility against the airline's four-condition policy, changes one flight, and books two new ones. The baseline cognitive signature is retrieve → evaluate-against-policy → present, with heavy structured communication to the user and explicit confirmation gates before every mutation. The agent reasons carefully and recalls earlier facts (payment method, loyalty tier, prior charges) from working memory rather than re-querying. Its weak spot is temporal grounding: it cites mutually inconsistent 'current dates' and, when a travel date is absent from a flight's schedule, resolves the ambiguity by assuming availability and commits a DB change on that unverified assumption. With no memory traps in this control condition, nothing jogs these errors and they persist unreviewed.
